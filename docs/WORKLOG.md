## 1. sample.txt をもとにしたオフラインHTMLの作成

### 指示
> 千葉県の災害に際し、県内外のボランティア募集状況を、sample.txt を参考に、Webページで公開したく、まずはオフラインでHTMLを作成してください。

（指示文の末尾に `Failed to authenticate: OAuth session expired and could not be refreshed` という文字列が付いていました。）

### 実施内容
- `sample.txt` を読み込みました。台風25号に関する2026年10月4日時点の一覧で、「全国OK」「千葉県内OK」「市町内・近隣のみ」「調整中・準備中・終了」の4区分、21市町の情報です。
- `index.html` を新しく作成しました。

### 判断と考察
- **オフラインで動くことを最優先にしました。** 外部の CDN・Webフォント・画像は一切使わず、CSS と JavaScript はすべてHTMLに直接書き込んでいます。ファイルをダブルクリックするだけで表示でき、災害時の通信が不安定な環境でも開けます。
- **フォントは端末に入っているものを使います。** Hiragino・Yu Gothic・Meiryo を順に指定しているので、Windows・macOS・iOS・Android のどれでも日本語が表示されます。
- **区分の構造は sample.txt に合わせました。** 情報量の多い2区分（全国・県内）はカード形式に、一覧性が重要な2区分（近隣・調整中）は表形式にしました。
- **絞り込みは「段階的強化（Progressive Enhancement）」で作りました。** HTMLは最初から全件を表示しておき、JavaScript は `hidden` 属性を切り替えるだけです。JavaScript が動かない環境でも、全件がそのまま読めます。
- **アクセシビリティに配慮しました。** 絞り込みボタンには `aria-pressed`、検索欄には `role="search"` と `aria-label` を付けています。
- **印刷用の設定を入れました。** `@media print` で絞り込み部分を隠し、カードが途中でページをまたがないようにしています（`break-inside: avoid`）。
- **リンクは付けませんでした。** sample.txt にURLがなく、推測でリンクを作ると誤った先に誘導するおそれがあるため、「詳細：社協ホームページ」などは文字だけにしました。
- **日付と曜日を確認しました。** sample.txt の「10月5日（月）」は、2026-10-05 が月曜日であることを確かめたうえで、そのまま使っています。
- 指示文末尾の OAuth エラーは、ユーザーの環境で表示された認証期限切れのメッセージと判断しました。HTML作成には影響しないことを回答で伝えています。

### 成果物
- `index.html`（初版）

### 残課題（この時点）
- 各社協のURLが不明
- 長柄町の募集人数が未掲載

## 2. バックアップと saigai-chiba.com の情報反映

### 指示
> index.html をバックアップ保存し、https://www.saigai-chiba.com/ から、可能な範囲で検索し、現時点の情報に更新した index.html を作成してください。

### 実施内容
1. `index.html` を `index_backup_20261004.html` にコピーしました。
2. WebFetch でトップページを取得し、内容の要約を得ました。
3. **要約は使わず、生のHTMLを `curl` で取得し、Python で検証し直しました。** 本文のテキストと、市町村ごとのリンク（詳細・行政HP・社協HP・Facebook）を、出てくる順番どおりに対応付けて抜き出しています。
4. お知らせページ（`/new/`）を取得しました。問い合わせ先の電話番号は、元の記事（2026/09/23）の生のHTMLで確認しています。
5. `index.html` を全面的に書き直しました。

### 判断と考察
- **要約結果をそのまま信用しなかった理由**：WebFetch は小さなモデルで内容を要約するため、数字や電話番号の読み違い、項目の取りこぼしが起こり得ます。災害情報では誤った電話番号や期間が大きな害になるため、掲載する事実はすべて生のHTMLで突き合わせました。
- **対象とする災害を広げました。** サイトには「令和8年8月千葉豪雨（8月13日）」と「台風25号」の2つが載っていたため、ページのタイトルを両方を含むものに変え、カードごとに災害タグを付けました。
- **区分の決め方**：サイトの「募集範囲」の項目をもとに、次のように分けました。
  - 全国：大網白里市、市原市、君津市
  - 千葉県内：佐倉市、千葉市、茂原市、長柄町
  - 市町内・近隣：八街市・成田市（sample.txt では「県内」でしたが、サイトでは近隣限定）、船橋市、袖ケ浦市、木更津市、八千代市、白井市、鎌ケ谷市、松戸市
  - 調整中・準備中：富津市（10/5 設置予定）、大多喜町、山武市、栄町、酒々井町、四街道市
  - 通常VCで対応：東金市、印西市、市川市、柏市、我孫子市、富里市、鴨川市、南房総市、いすみ市（表形式）
- **情報源を混ぜずに区別しました。** 公式のまとめサイトには募集人数やニーズ件数が載っていません。そこで、開設状況・期間・範囲は公式サイトの記載を「本文」に、sample.txt にしかない人数・ニーズ・作業内容は「補足」欄に分けて表示しています。どこから来た情報かを、読む人が区別できるようにするためです。
- **食い違いは消さずに表示しました。** 松戸市（sample.txt では「9/16 終了」、サイトでは「開設中」）と鎌ケ谷市（「中止」と「開設中」）は、どちらが正しいか判断できる材料がありません。公式サイトの記載を表示したうえで、「情報差異あり」のタグを付けています。どちらか一方を黙って採用すると、終了した地域に人を送ってしまう危険があるためです。
- **参加前の注意事項を追加しました。** 問い合わせ先（080-2300-1450、9:00〜16:30）、ボランティアバスは県のセンターを通して調整すること、ボランティア活動保険、高速道路の無料措置を載せています。保険と高速道路の具体的な条件（金額や期限など）は、要約でしか確認できていないため本文には書かず、各記事へのリンクにとどめました。
- **リンクの設定**：外部リンクには `target="_blank" rel="noopener"` を付けています。一部の社協HPは `http://` のままですが、リンク先として開くだけなので、混在コンテンツの問題は起きません。

## 3. LINE オープンチャットでの配布可否の検討

### 指示
> index.html を LINE のオープンチャットに転送し、閲覧することは可能ですか？ 留意点などあれば教えてください。

### 回答の要点
- **結論：HTMLファイルをそのまま送るのは推奨しない。Webで公開してURLを共有する方法を推奨。**
- 推奨しない理由：
  1. **開けない人が多い**：LINE のアプリ内ではHTMLをページとして表示できません。iOS のプレビューでは JavaScript が動かないことがあり、Android では中身がソースのまま表示されることがあります。
  2. **古い情報が残る**：送ったファイルは更新できません。送り直すたびに古い版がトーク履歴に残り、終了した地域に人が向かうおそれがあります。LINE のファイルには保存期間もあります。
  3. **警戒されやすい**：誰でも参加できるオープンチャットで、知らない人からHTMLファイルが届くと、詐欺やウイルスを警戒されます。
- 提案した方法：①Webで公開（GitHub Pages・Netlify など）、②要点の文章とURLをあわせて投稿、③画面の画像を補助的に投稿。

### 判断と考察
- LINE の細かな仕様（送れるファイル形式や保存期間）は、バージョンや端末によって変わり、こちらでは確かめられません。そのため、確定した事実ではなく「一般的な傾向」として回答しました。
- 災害情報では「情報の鮮度」と「一つの正しい情報源（Single Source of Truth）」が最も重要だと考え、URL一つで常に最新を見せる方法を強く推しました。

## 6. Vercel での公開手順

### 指示
> Vercel で公開したく、下記に sign in しましたので、公開手順を教えてください。https://vercel.com/sumitarous-projects

### 回答の要点
- Add New → Project → GitHub と連携（**Only select repositories** で対象のリポジトリだけを許可）→ Import → Framework Preset を `Other` に → Deploy。
- main に push すると、自動で本番に再公開されます。

### 判断と考察
- **ビルドの設定は不要です。** 静的なHTML1枚なので、Build Command と Output Directory は空のままで構いません。
- **GitHub に与える権限は最小限にしました。** Vercel には対象のリポジトリだけを見せる設定を勧めています。
- **プレビュー用URLの注意**：Vercel の初期設定では、push ごとに作られるプレビュー用URLはログインしないと見られません（Vercel Authentication）。共有するのは本番用のURLに限るよう伝えています。
- **無料プラン（Hobby）は非商用利用が前提です。** 今回のボランティア情報の公開は、その範囲に収まると判断しました。
- **URLを一つに絞ることを勧めました。** GitHub Pages と併用すると、片方の更新漏れで情報が食い違うおそれがあるためです。

## 10. 技術的な設計判断のまとめ

| 項目 | 採用したもの | 理由 |
|---|---|---|
| 構成 | HTML1枚（CSS と JS を内包） | オフラインでも動き、置くだけで公開でき、ビルドが不要 |
| 外部依存 | なし | 通信が不安定でも表示でき、CDN の障害やプライバシーの心配がない |
| データの持ち方 | HTMLに直接記述 | 初期対応を早くするため。更新の手間が増えるので、将来は JSON に分ける余地あり（後述） |
| 絞り込み | `hidden` 属性の切り替えと `textContent` の部分一致 | JavaScript が動かなくても全件が読める |
| 情報源の区別 | 本文＝公式／青枠＝募集サイト／灰色＝独自集計／タグ＝差異 | 情報の出所を読む人が判断できるようにする |
| 色 | CSS 変数で区分ごとに色分け | 区分を色と見出しの両方で見分けられる（色だけに頼らない） |
| 公開先 | Vercel（本番）、GitHub をソースとして管理 | push で自動公開、HTTPS、無料 |

### 将来の改善案
1. **データとHTMLを分ける**：市町村の情報を `data.json` にまとめ、HTMLは表示だけを担当するようにします。更新するときの書き間違いや、タグの閉じ忘れを防げます。
2. **更新日時を一か所で管理する**：今は「○月○日時点」がヘッダーとフッターの2か所に書かれています。1か所にまとめて自動で反映させます。
3. **リンク切れの定期チェック**：GitHub Actions で定期的にリンクを確認します（例：lychee）。
4. **HTMLの自動チェック**：push のたびに html-validate などでHTMLの書き方を検証します。
5. **OGP の設定**：LINE などで共有したときに、タイトル・説明・画像がきれいに表示されるようにします。
